作ったもの

創作評価ベンチ

生成AIが書いた物語を自動で採点し、生成のやり方ごとの出来を比べるツール

何をするか
同じ題材で、生成のやり方を変えて物語を書かせます。創作AIだけで書く「創作AI 単体」と、創作AIが書いたものを編集者AIが直す「創作AI ＋ 編集者AI」、それぞれに憲法を与える／与えない、の4条件です。できた物語を共通の基準で採点し、どのやり方が良いかを数字で比べます。
採点の基準
自分の創作のために作ってきた次の仕様を使います。
  • 作品ごとの「憲法」（守るべき創作上のルール）
  • 独自に定義した 636語の概念語彙
  • 出来事のつながりを表す因果グラフ
  • 作品ごとに設定した目標
ねらい
生成AIの出力は「なんとなく良い／悪い」で判断されがちです。先に基準を言葉にしておけば、同じ物差しで比べられます。仕事で Now Assist を評価してきたやり方を、創作の領域で試す試みでもあります。

できること

仕事で担当してきたこと（ServiceNow）

7名のチームで、リーダー補佐・評価検証を担当。扱ったモジュールは ITSM、Creator、SPM、Now Assist です（バージョンは Xanadu〜Australia）。

生成AI（Now Assist・AI検索・AI Agent）の導入と評価

  • ServiceNow 社の導入支援担当との打ち合わせ、技術的なヒアリング
  • 製品群を網羅したマニュアルと、AIツール選定資料の作成
  • システムプロンプトの編集による生成機能の調整
  • AIガードレールの設定（プロンプトインジェクション対策など）
  • 生成された文章のセキュリティ品質を測る指標づくりと、機能評価
  • AI Agent Studio のテーブル構成の調査

SPM の AI 機能の検証

  • インポートセットと変換マップを使ったダミーデータの準備
  • プロジェクト管理系の AI 部品の洗い出しと、エージェント型ワークフローでどの部品が呼ばれるかの可視化
  • 期待結果の洗い出しと、部品ごとの粒度に合わせたテスト密度の調整

リリースと運用の計画

  • リリース手順書の策定（デグレ・リグレ観点の整理、全画面テストと動作確認テストの設計）
  • Now Assist プラグイン展開の詳細設計書の作成
  • リリース後のプラグインのライフサイクルを考えた運用手順の作成
  • 権限ロール管理の運用マニュアル作成
  • ログの取得・保管ルールの策定、従量課金に向けたログ運用とダッシュボードで見る観点の整理

機能開発・保守（JavaScript）

  • 特定ロールにレコードの作成・削除機能を付与するエンハンス
  • Agile 2.0 のバーンアップチャートの不具合改修（調査、リグレ確認、テスト計画）
  • ガントチャートのロール別 UI 表示のカスタマイズ（スクリプトインクルードで実装）
  • 通知機能の不具合の原因調査と、顧客・ServiceNow 社への問い合わせ
  • メジャーアップグレード対応の自動化（sys_id の存在を確認するバックグラウンドスクリプト、clone_admin ユーザーをスケジュールで有効化するワークフロー）
